# MemDiag Web UI 实现计划

## 一、功能映射

### CLI 命令 → Web UI 功能

| CLI 命令 | Web UI 模块 | 说明 |
|---------|-----------|------|
| `memdiag histogram` | 堆内存分析页 | 堆直方图、类分布 |
| `memdiag threads` | 线程分析页 | 线程状态、堆栈 |
| `memdiag diagnose` | 诊断报告页 | 自动诊断、问题识别 |
| `memdiag native` | 堆外内存页 | Native 内存分析 |
| `memdiag snapshot` | 快照管理页 | 快照保存/加载/对比 |
| `memdiag diff` | 对比分析页 | 堆差异对比 |
| `memdiag report` | 报告导出页 | HTML/JSON 报告 |
| `memdiag allocations` | 分配追踪页 | 实时分配统计 |
| `memdiag methods` | 方法监控页 | 方法执行统计 |
| `memdiag agent` | Agent 管理页 | Agent 状态/配置 |

---

## 二、技术选型

### 前端技术栈

| 技术 | 选型 | 理由 |
|------|------|------|
| **模板引擎** | Thymeleaf | Spring Boot 原生支持，与后端集成好 |
| **CSS 框架** | Bootstrap 5 | 快速构建响应式界面 |
| **图表库** | Chart.js | 轻量级，支持多种图表类型 |
| **WebSocket** | SockJS + STOMP | 实时数据推送 |

### 为什么不用 React/Vue？

1. **项目已有 Java 技术栈**，减少技术复杂度
2. **快速交付**，Thymeleaf + Bootstrap 可以快速出活
3. **维护简单**，Java 团队更容易维护
4. **后续可演进**，未来可以分离为前后端架构

## 四、核心功能模块设计

### 4.1 连接管理模块

**功能**：
- 创建连接（支持 PID 或 Agent host:port）
- 连接列表展示
- 连接状态监控
- 断开连接

**API 对应**：
```
GET    /api/v1/connections
POST   /api/v1/connections/{id}
DELETE /api/v1/connections/{id}
```

### 4.2 堆内存分析模块

**功能**：
- 堆直方图可视化（饼图/柱状图）
- Top N 类展示
- 按大小/数量排序
- 类搜索和过滤

**图表**：
- 饼图：显示各类占比
- 柱状图：显示 Top N 大小

### 4.3 线程分析模块

**功能**：
- 线程状态汇总（RUNNABLE/WAITING/TIMED_WAITING/BLOCKED）
- 线程列表
- 堆栈追踪展示
- 死锁检测提示

### 4.4 诊断报告模块

**功能**：
- 诊断结果展示
- 问题分类展示
- 建议展示
- 一键导出报告

### 4.5 快照管理模块

**功能**：
- 快照列表
- 创建快照
- 加载快照
- 删除快照
- 快照对比

### 4.6 实时数据模块（WebSocket）

**功能**：
- 实时分配速率
- 实时堆内存使用
- Agent 状态更新

## 八、实施建议

1. **先做 P0 功能**，确保核心体验
2. **每个页面独立测试**，确保质量
3. **复用已有 API**，减少后端开发
4. **优先桌面端体验**，后续优化移动端
